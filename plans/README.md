## Dependency notes

- **005 must land before 006.** 006 refactors the hottest code path (the agent loop); 005 adds the
  characterization tests that catch a regression. Refactoring it untested is the main risk in this set.
- **001 should land before 002.** 002's emitter is typed against the SSE event union 001 defines.
  002 can be done with a locally-defined union if 001 is deferred, but then it must be reconciled later.
- **003** is independent but is cleaner if 001's tool-name constants exist (it can import them instead
  of re-listing strings). Safe to do standalone.
- **004** is independent. Pairs naturally after 002 (both touch the chat route's `llm.stream(...)` call).
- **008 before 009** reduces churn (009 removes imports that 008 also moves), but they're independent.
- The quick wins (002, 003, 004, 007) carry LOW risk and can land in any order once deps are met.

## Maintainer conventions every executor must follow

- **Runtime is bun.** Never `npm`/`node` — they aren't on PATH. Use `bun` / `bunx`.
- **The maintainer commits, not the executor.** Leave the tree clean; do NOT `git commit` or push.
- **Backward-compatible / additive.** Frontend (Vercel) and backend (Fly) deploy on different
  cadences, so a new version routinely runs against an older counterpart. Prefer adding fields/types
  over renaming or removing; tolerate unknown/missing fields. (See `CLAUDE.md`.)
- **Keep docs current.** Any change to how the pieces connect updates `docs/ARCHITECTURE.md`; any
  dependency change updates `docs/STACK.md` — in the *same* change. Each plan's done-criteria says
  which doc, if any.
- **Verify with `build`, not just `typecheck`, on the frontend** — `tsc -b --noEmit` can false-green
  in the project-references setup; `bun run build` is the real gate.
